# WCS Colour Language and Speaker-Level Psycholinguistics

## Scientific question

The primary question is:

> **Is the colour vocabulary of a speaker's primary language related to that speaker's own linguistic representation of physical colour?**

The study is an inferential regression analysis of the complete available WCS speaker sample. It is not a prediction study.

The principal null hypothesis is

\[
H_0:\text{language colour vocabulary is unrelated to speaker-level colour representation},
\]

against

\[
H_1:\text{language colour vocabulary is related to speaker-level colour representation}.
\]

Two speaker-level representations are examined: linguistic colour resolution and information efficiency with respect to physical colour.

## Data

The project uses the World Color Survey naming responses to 330 standardized colour chips from 110 languages. The canonical local dataset is stored at

```text
data/processed/wcs_responses.csv.gz
```

and is created once by `setup_dataset.py`. `run_all.py` reads the stored dataset and does not download data.

The supplied real-data sample contains 2,616 speakers and 863,280 naming-response rows.

## Part 1 — linguistic colour resolution

For a speaker and chip pair,

\[
Z_{sij}=1\{Y_{si}\ne Y_{sj}\}.
\]

Physical distance is Euclidean CIELAB distance,

\[
d_{ij}=\|\mathbf x_i-\mathbf x_j\|_2.
\]

All valid unordered pairs are used. For a complete speaker this is 54,285 pairs.

After deterministic aggregation into physical-distance bins,

\[
Y_{sb}\sim\operatorname{Binomial}(N_{sb},p_{sb})
\]

is used as a working distribution, with

\[
\operatorname{logit}(p_{sb})=\alpha+f(d_b)+f(d_b)\log K_l,
\]

where \(f\) is a pre-specified cubic B-spline with eight knots.

Because raw pairs overlap in chips and speakers, no i.i.d. assumption is made. Generalized estimating equations with a robust sandwich covariance cluster the inference at language level.

The primary test is

\[
H_0:\gamma_1=\cdots=\gamma_9=0,
\]

where the \(\gamma_r\) are the spline-by-language-vocabulary interaction coefficients. A joint robust Wald \(\chi^2_9\) test is used.

## Part 2 — physical-colour information

The exact chip identity is not used as the physical information variable. Instead, the 330 CIELAB points are partitioned into 20 physical bins using CIELAB coordinates only.

For speaker \(s\),

\[
I_s(B;Y)=\sum_{b,y}p_s(b,y)\log\frac{p_s(b,y)}{p_s(b)p_s(y)},
\]

and the first-order Miller–Madow correction is

\[
\widehat I_{MM}=\widehat I_{MLE}+\frac{r+c-q-1}{2n}.
\]

Information efficiency is

\[
E_s=\widehat I_{MM}/H(B).
\]

The primary regression is the pre-specified linear fractional-response model

\[
\operatorname{logit}\{\mathbb E(E_s\mid K_l)\}=\beta_0+\beta_1\log K_l.
\]

The primary hypothesis is

\[
H_0:\beta_1=0.
\]

A language-clustered robust Wald \(\chi^2_1\) test is used.

A fixed quadratic model is included only as a sensitivity analysis. There is no cross-validation or model-selection step.

## Statistical assumptions

The analysis does not assume that raw observations are independent and identically distributed. The main assumptions are that the 110 language clusters are approximately independent for robust inference, that speakers are exchangeable within a language for the descriptive bootstrap, that the Part 1 mean relationship is adequately represented by a smooth cubic spline, that the Part 2 logistic mean is correctly bounded in (0,1), that the CIELAB geometry and physical partition are useful fixed representations, and that the observed valid responses define the estimands when responses are missing.

The language vocabulary \(K_l\) is a constructed covariate calculated from the observed WCS naming system. The regression inference is therefore conditional on the realized vocabulary measurements, uncertainty in the construction of \(K_l\) is not separately modelled.

## Outputs

Each part deletes its own previous generated result directory before writing a fresh run. Thus `results/project1/` and `results/project2/` contain only outputs generated by the current analysis.

Run:

```bash
python -m pytest -q
python run_all.py
```

The test suite contains mathematical and software checks, the complete current suite passes in the supplied environment.
